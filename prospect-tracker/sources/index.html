Data: sources, attribution and what we publish

upstreams we read, artifacts we publish

PROSPX grades are a consensus of seven industry sources. No source's rankings or reports are republished wholesale; excerpts carry attribution. Trademarks and data belong to their owners.

Sources with a question or concern: arkndjl@gmail.com.

Building on the data: the data we publish.

Where the data comes from

FanGraphs

Prospect rankings, FV grades, tool grades, and scouting reports (one of the seven PROSPX consensus inputs); league stats and park factors.

MLB Pipeline

Prospect rankings and grades (consensus input); draft bonus pools and slot values.

Baseball America

Prospect rankings and grades (consensus input).

ESPN

Prospect rankings (consensus input); team logo imagery on internal surfaces.

The Athletic

Prospect rankings (consensus input).

Just Baseball

Prospect rankings (consensus input).

TJStats

Prospect rankings (consensus input) and movers wire.

MLB Stats API / Baseball Savant

Game logs, transactions, rosters, the sabermetrics feed (league wOBA constants; the fielding and framing runs behind DEM+), Statcast tracking data (pitch, batted-ball and zone metrics), and player headshots via MLB static media.

Baseball-Reference

war_daily (bWAR): the run frame the served eWAR is built on and the source the Hall of Fame board reproduces, plus historical player pages.

pybaseball

Open-source Python toolkit used to pull Statcast, FanGraphs, and Baseball-Reference data programmatically.

Spotrac

Contracts, payrolls, free-agent classes, and international signing trackers.

The data we publish

contents, cadence and stability of every served artifact

Every model writes a static JSON file under /data/; the site reads the same files. No key, no quota, no sign-up. 48 artifacts documented below, 26 of them stable.

Not promised: version headers, deprecation windows, uptime, or byte layout. Fields can be added without notice. A field named here keeps its name and meaning.

30 more files stay local (model internals and pipeline inputs no page fetches) and are not listed.

CSV from any board

Download CSV writes what is on screen: current sort, filters and display formats. Use the artifacts for whole boards.

eFV movement alerts: feed only, no delivery

Each rebuild publishes the biggest genuine eFV moves, with drivers, to /data/efv_alerts.json. Nothing is emailed or pushed; the artifact's delivery field says so.

A move with an endpoint at the eFV 20 floor is a player entering or leaving the graded pool, not a re-grade; filter on at_floor.

Do pitchers and hitters mean the same thing at the same grade?

The audit behind the question people actually ask about eFV: why does it carry so few pitchers near the top? It answers with outcomes rather than with a comparison to another board, because a source is not over-grading pitchers by disagreeing with us, only by disagreeing with what those pitchers produced. Mean realized first-six-year WAR by side within each grade band, for the served eFV grade and for consensus FV, on the resolved pool with players who never reached the majors carried at zero.

/data/xfv_side_calibration_eval.json
on change · 6 KB · as of August 12, 2026

experimental: shape can change or the file can disappear on any run
The served eFV grade is retrospective on this pool, so this measures the SHIPPED grade map against outcomes and is NOT an out-of-sample forecast. Cells under 30 rows a side are reported and not scored; the top pitcher cells are thin by construction and that emptiness is the finding rather than a cell to score.

eFV vs a rebuilt consensus

The fairness control behind the head-to-head claim. eFV is normally compared against the consensus AS SERVED, so part of its lead could be eFV beating the blending rather than beating the scouts. This rebuilds the consensus from measured per-source precision and re-runs the comparison on identical rows, under both registered noise-floor estimators, with the decision rule fixed in advance and two adversarial reweighting controls.

/data/xfv_denoised_baseline_eval.json
on change · 13 KB · as of August 11, 2026

experimental: shape can change or the file can disappear on any run
`basis.vintage_disciplined` is FALSE by construction and the number must never be quoted as out of sample: per-source precision is estimable only for board years 2023-2026, so the baseline is defined using rows it also scores. Read `primary_corrected_amendment_2`, not `primary_as_registered`.
Shape pinned by test_denoised_baseline_lab.py

Which frame the head-to-head is scored on

eFV carries one grade per player, fitted at that player's decision year, while the common set carries a consensus read for every base year. That makes the comparison frame a choice, and the choice decides the answer. This scores three frames inside the same bootstrap draws: every base year, post-debut reads removed, and base year equal to the decision year. Each gets its own floor.

/data/xfv_headtohead_frame_eval.json
on change · 4 KB · as of August 13, 2026

experimental: shape can change or the file can disappear on any run
The middle frame is the only one that clears a floor and it is deliberately NOT the headline: it removes the rows where the consensus is advantaged while keeping those where eFV is, so its margin is partly an artifact of that asymmetry. Read `vintage_matched`, which is the symmetric contest and reads a tie at the smallest floor of the three.
Shape pinned by test_headtohead_frame.py
