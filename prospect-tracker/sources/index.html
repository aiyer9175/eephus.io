Data: sources, attribution and what we publish

every upstream the platform reads, and every artifact the platform serves back

eephus.io is a sabermetric analysis platform. PROSPX grades are a consensus built across seven independent industry sources - the value added is the aggregation, calibration, and track-record audit, not any single list. No source's rankings or reports are republished wholesale; excerpts appear with attribution in the spirit of commentary and analysis. All trademarks and data remain the property of their owners.

If you represent one of these sources and have a question or concern, email arkndjl@gmail.com and it will be addressed promptly.

Building something on top of this? Skip to the data we publish for the artifact catalog, the update cadence and what each file is safe to depend on.

The data we publish

every artifact the site serves, what is in it, and how much it can be trusted

Every model on eephus.io writes its output to a static JSON file under /data/, and the site itself is just a reader of those files. They are public. There is no key, no quota and no sign-up, because there is no server to sign up to: fetch the URL and you have the same payload the board is rendering from. 26 artifacts are documented below, 21 of them stable.

What is deliberately NOT promised: a version header, a deprecation window, an uptime target, or a stable byte layout. A nightly pipeline writes these and a nightly pipeline sometimes fails. Fields get added without warning. What does hold is that a field named on this page keeps its name and its meaning, because the site reads the same field and a rename breaks us first.

30 more files stay local by design (model internals and pipeline inputs that no page fetches), and they are left off this list rather than linked, so nothing here points at a URL that does not resolve.

CSV, straight off any board

Every board on the site now carries a Download CSV control above its table. It writes exactly what is on screen: your current sort, your current filters, and each number in the format the page displays it. That makes it the right tool for "the twelve rows I am looking at" and the wrong tool for "the whole board", which is what the artifacts above are for.

eFV movement alerts: the feed exists, the delivery does not

The biggest genuine eFV moves from each rebuild are published to /data/efv_alerts.json with the driving explainer attached. Nothing is emailed or pushed from it yet: per-user watchlists need the account layer, which is not switched on. The artifact says so about itself in a delivery field, so a consumer reading the JSON alone cannot mistake it for a live alert stream.

One thing worth knowing before you rank on the delta: about half the movers on a typical rebuild have an endpoint at eFV 20, which is the model floor. Those rows are a player entering or leaving the graded pool, not a re-grade. Each row carries an at_floor flag so you can separate the two in one predicate.
