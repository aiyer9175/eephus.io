=== NOTES ===
Read this first: /dfs/ has no data. data/dfs.json is absent from the repo, so in production that page is a red failure box and nothing else. Whatever else ships, someone needs to run the DFS daily slate step; until then a reader sees only the error state, which is now at least a working error state rather than four dead tabs.

The headline bug is the optimizer. It was not a rendering problem or an empty-state problem, it was wrong: it told the reader no lineup satisfied his constraints while a legal lineup costing 68% of his cap sat in the pool, and it would have done that on real slates too, because three outfield slots sharing one pool is the normal shape of a DFS roster, not an edge case. That one only surfaces if you actually import salaries and press the button.

The second-worst was quieter. The parlay builder printed 'EV / unit -0.655' for a ticket with no prices on it. Nothing was undefined or NaN, nothing threw; it just multiplied missing odds as though they were even money and published the result to three decimals on a gambling page. Both of those are exactly the class of defect a stubbed DOM cannot see.

Three judgement calls I want on the record. First, I did not change the 'Hold' number in the vig calculator even though its label was arguably wrong, because betting_model.hold_pct defines it the same way, a test pins it at 4.7619, and the game cards publish it; desyncing the calculator from the board to win a definitional argument would have been the worse trade. I corrected the copy and added the balanced-handle figure beside it instead. Second, I did not touch the My Bets sign-in merge, which is genuinely broken and will orphan a logged-out reader's rows: every fix crosses into a file or a pinned test that is not mine, and the path is inert in this build so I could not exercise it either way. It needs an owner decision, not a guess from me. Third, the gold-on-cream contrast failures resolved from real tokens, so they were not 'hardcoded colours that survived' in the letter of the brief, but 2.13:1 on 9px uppercase text is unreadable and it is my module's CSS, so I fixed it by moving the colour to the border rather than by inventing a token.

What I could not verify: the signed-in account path for My Bets (no Supabase config), and /dfs/ against real data (the artifact does not exist, so I used route-injected payloads built to dfs_export.build_payload's exact shape plus a DraftKings-shaped salary CSV). The optimizer fix is validated against synthetic salaries with realistic spreads, not against a real DraftKings export; the join logic itself is unchanged and matched 120 of 120 rows.

One thing I found and discarded as an artifact of my own test data, in case it resurfaces: dfs.js's nameKey strips digits, so my first synthetic pool of 'NYM Bat 1' through 'NYM Bat 14' all collapsed onto one key and the salary import silently matched a single player per team. Real MLB names contain no digits, so this is not a product bug, but it did cost me a debugging pass and it would bite anyone else generating test names the same way.
