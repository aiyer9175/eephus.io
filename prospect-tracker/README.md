# eephus.io

**eephus.io** is an editorial baseball-analytics portal. It has four top-level
sections — a magazine-style **Home**, long-form **Articles**, the **PROSPX**
prospect tracker, and the **Development Team** page. PROSPX (a consensus
FV-based MiLB prospect tracker with surplus-value analytics) is one module
within the larger site.

The site is **plain static files** — no JS framework or bundler. The editorial
pages (Home / Articles / Team) are generated by a small Python build step
(`build_site.py`); PROSPX is a single self-contained `index.html` that reads
generated JSON data; the data itself is produced by a Python pipeline
(`run_monthly.py`).

## Sections & routes

| Route | Page | Source |
|---|---|---|
| `/` | Home (brand hero + module cards) | generated by `build_site.py` |
| `/articles/` | Articles index (card grid) | generated from `content/articles/*.md` |
| `/articles/<slug>/` | Individual article | generated from `content/articles/<slug>.md` |
| `/prospx/` | PROSPX prospect tracker app | `prospx/index.html` |
| `/team/` | Development Team | generated from `content/team.json` |

## Install

```bash
pip install -r requirements.txt
```

## Running the site

```bash
# 1. Build the editorial pages (Home, Articles, Team) from content/
python build_site.py

# 2. Serve the whole site at the domain root
python -m http.server 8000
#    open http://localhost:8000/        (Home)
#         http://localhost:8000/prospx/ (PROSPX app)
```

Serve from the **repository root** so the root-absolute asset paths
(`/data/…`, `/vendor/…`, `/assets/…`) resolve — that mirrors production, where
the site is served at the `eephus.io` root.

### Run tests

```bash
python -m pytest -q
```

## Adding an article

Articles are Markdown files — no code changes needed:

1. Create `content/articles/<slug>.md` with frontmatter:

   ```markdown
   ---
   title: My Headline
   author: Jane Doe
   handle: janedoe          # X/Twitter handle (optional; omit the line if none)
   date: 2026-06-05         # YYYY-MM-DD — drives ordering (newest first)
   summary: One or two sentences shown on the card and as the article dek.
   ---

   Body in Markdown. Paragraphs, **bold**, *italic*, [links](https://…),
   lists, and headings all work.

   Embed a YouTube clip on its own line:

   @youtube: https://youtu.be/VIDEO_ID
   ```

2. Re-run the build:

   ```bash
   python build_site.py
   ```

   This regenerates `/articles/` and writes `/articles/<slug>/index.html`.

## `run_monthly.py` — the data pipeline

`run_monthly.py` is the **data** pipeline for PROSPX. It is independent of the
site build above. It scrapes the public sources, ingests the hand-maintained
rankings in `data/manual_rankings.csv`, rebuilds the SQLite cache
(`prospects.db`), and exports the JSON that the PROSPX app reads
(`data/timeseries.json` plus the lazy sidecars: graduates / inactive /
rosters_by_org / draft / overseas / ifa).

Run it **monthly**, or any time you edit `data/manual_rankings.csv`:

```bash
python run_monthly.py                 # full refresh (scrape + ingest + export)
python run_monthly.py --rebuild-only  # no scrape; re-ingest DB + re-export JSON (fast)
python run_monthly.py --skip-stats    # skip MLB / MiLB stat fetches
python run_monthly.py --force         # bypass HTTP + DB freshness cache
python run_monthly.py --dry-run       # diagnostic; no DB writes, no export
python run_monthly.py --workers 8     # cap thread-pool size
python run_monthly.py --out-dir path  # write data/*.json elsewhere
```

After a data refresh you do **not** need to rebuild the site (PROSPX reads the
JSON at runtime), but it's harmless to run `build_site.py` too.

### Edit the prospect lists

```
data/manual_rankings.csv
```

Columns: `source,snapshot_date,interval_label,player_name,position,org,rank,fv,status,birth_date`
Valid `source`: `fangraphs`, `espn`, `just_baseball`, `tjstats`, `baseball_america`, `mlb_pipeline`, `the_athletic`.
Valid `status`: `active`, `debuted`, `injured_list`, `off_list`.

## Deploy

The build output is plain static files, so it deploys to **any static host**
(object store + CDN, Netlify, Vercel, Cloudflare Pages, a plain web server, …):

```bash
python run_monthly.py     # (when data changed) refresh data/*.json
python build_site.py      # regenerate the editorial pages
# then publish the repository contents (served at the domain root)
```

Publish these so the routes resolve: `index.html`, `articles/`, `prospx/`,
`team/`, `assets/`, `data/`, `vendor/`. The site must be served at the **domain
root** (e.g. `eephus.io`) so the root-absolute asset paths work.

## Project layout

```
eephus.io / prospect-tracker/
├── index.html                 # Home          (generated by build_site.py)
├── articles/                  # Articles index + per-article pages (generated)
├── team/                      # Development Team (generated)
├── prospx/index.html          # PROSPX app (self-contained)
├── assets/site.css            # shared site theme + nav (editorial pages + PROSPX nav)
├── content/                   # editorial source (edit these)
│   ├── articles/*.md          #   article markdown + frontmatter
│   └── team.json              #   development-team roster
├── build_site.py              # static-site generator (editorial pages)
├── data/                      # generated PROSPX data (timeseries.json + sidecars)
│   └── manual_rankings.csv    #   prospect source-of-truth (edit by hand)
├── prospects.db               # SQLite cache (regenerable)
├── run_monthly.py             # PROSPX data pipeline entry point
├── consensus.py               # FV grid + unweighted aggregation
├── value_framework.py         # FV→WAR→$ surplus-value engine
├── storage.py                 # SQLite schema + JSON export
├── scrapers.py / stats.py / trades.py / …   # ingest + enrichment
└── test_*.py                  # test suite
```
